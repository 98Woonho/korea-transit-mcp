# 버스 이동 안내

사용자가 "어디서 몇 번을 타면 언제 오는지"를 한 번에 알 수 있게 안내한다.
핵심은 **이름이 같은 정류장(길 건너편) 중 올바른 쪽을 골라 주는 것**과 **실제 데이터로만 답하는 것**이다.

## 준비

korea-transit MCP 도구가 필요하다. `korea-transit` 플러그인으로 설치했다면 이미 연결되어 있다.
도구 목록에 `find_direct_routes`(이름 앞에 플러그인 접두사가 붙을 수 있음)가 없으면 안내를 시작하지 말고, 설치 방법을 알려 준다.

```
/plugin marketplace add 98Woonho/korea-transit-mcp
/plugin install korea-transit@korea-transit-mcp
```

## 진행 순서

### 1. 도시 확인
`list_cities(query)`로 cityCode를 얻는다. 도시가 대화에 드러나지 않으면 먼저 묻는다.
정류장 이름(예: "시청역")은 여러 도시에 있어서 추측하면 엉뚱한 도시를 안내하게 된다.
서울은 TAGO에 없으므로 지원하지 않는다고 바로 알린다.

### 2. 출발·도착 정류장 후보 모으기
`search_bus_stops(cityCode, name)`를 출발지와 도착지에 각각 한 번씩 호출한다.

- 결과에서 **이름이 같은 정류장은 모두** 후보로 모은다(각 최대 5개). 이름이 같으면 대개 도로 양편의 정류장이고, 어느 쪽에서 타야 하는지는 다음 단계의 도구가 판별한다. 여기서 하나만 고르면 반대 방향 버스를 안내할 위험이 있다.
- 이름이 다른 후보만 여럿 나오면(예: "시청" → 대전광역시청, 시청역, 시청.교육청) 사용자의 표현에 가장 가까운 것을 고르고, 답변에 어떤 정류장으로 해석했는지 밝힌다. 판단이 어려우면 사용자에게 묻는다.
- 하나의 cityCode에 인접 시·군이 묶여 있을 수 있다(대전 25 = 대전광역시/계룡시). 다른 시의 같은 이름 정류장이 섞이지 않았는지 본다.
- 건물명이나 주소처럼 정류장 이름이 아니라 검색이 안 되면, 근처 정류장 이름을 물어본다. 공공 API에 주소 → 좌표 변환이 없다. 사용자가 좌표를 주면 `find_nearby_stops`를 쓴다.

### 3. 직통 노선 찾기
`find_direct_routes(cityCode, fromNodeIds, toNodeIds)`에 2단계의 후보를 **모두** 넘긴다.
결과의 `fromNodeId`가 실제로 타야 하는 정류장이다. 결과는 이동 정류장 수가 적은 순이다.

결과가 비어 있으면 갈아타지 않고 가는 노선이 없다는 뜻이다. 아래 "직통 노선이 없을 때"로 간다.

### 4. 실시간 도착 정보
3단계 결과의 `fromNodeId`별로 `get_bus_arrivals(cityCode, nodeId)`를 **한 번씩만** 호출하고, 직통 노선의 `routeId`로 걸러 낸다.
노선마다 따로 호출하지 않는 이유는 공공 API 일일 호출 한도를 아끼기 위해서다.

도착 정보에 없는 직통 노선은 지금 다가오는 차가 없는 것이다. 늦은 시간이면 `search_routes`로 첫차·막차 시각을 확인해 알려 준다.

## 답변 형식

```
🚏 **시청역(32410)**에서 타세요 — 목련아파트 방면 정류장입니다.

| 버스 | 도착 | 이동 |
|---|---|---|
| 617번 (간선) | 곧 도착 · 1정류장 전 | 1정류장 |
| 106번 (간선) | 약 4분 · 3정류장 전 | 1정류장 |
| 707번 (간선) | 약 11분 · 7정류장 전 | 1정류장 |

⚠️ 길 건너편 시청역(32390)은 반대 방향(시청.교육청 방면)입니다.
```

- **탈 정류장을 맨 앞에** 쓰고, 정류장 번호와 "○○ 방면"(`nextStop`)을 붙인다. 현장에서 표지판의 정류장 번호로 확인할 수 있기 때문이다.
- 이름이 같은 반대편 정류장이 후보에 있었다면 **반대편 정류장이 아니라는 주의**를 붙인다. 이 스킬이 가장 쓸모 있는 부분이다.
- `arrivingSoon`이 true면 분 대신 "곧 도착"이라고 쓴다.
- 노선이 많으면 도착이 빠른 3~5개만 표로 보여 준다. 사용자가 원하면 나머지를 보여 준다.
- `viaTurnaround`가 true인 노선은 "종점을 돌아서 가는 노선이라, 회차지에서 하차를 요청받을 수 있다"고 알린다.
- 도착 시간은 실시간 추정치라 달라질 수 있다는 점은 한 줄이면 충분하다.

## 직통 노선이 없을 때

`find_transfer_routes(cityCode, fromNodeIds, toNodeIds)`에 3단계와 **같은 후보 목록**을 넘긴다.
이 도구는 두 노선의 경유 순서와 방향을 대조해서 실제로 이어지는 1회 환승 경로만 돌려준다.
환승 경로는 **이 도구 결과에 있는 것만** 안내한다. 노선 번호만 보고 "어디서 갈아타면 될 것"이라고 추측하지 않는다.

- 결과는 두 구간 정류장 수 합(`totalStops`)이 적은 순이다. 맨 위 1~2개를 추천하고, 나머지는 사용자가 원하면 보여 준다.
- 각 구간의 `fromStopNo`·`toStopNo`로 **탈 곳, 갈아탈 곳, 내릴 곳의 정류장 번호**를 모두 적는다. 갈아탈 때도 길 건너편 정류장과 헷갈리기 쉽기 때문이다.
- `sameStop`이 false면 내린 정류장에서 갈아탈 정류장까지 걸어가야 한다. `walkM`(직선거리)과 정류장 번호를 함께 알리고, 길을 건너야 할 수 있다고 덧붙인다.
- 정류장 수 기준이라 실제 소요 시간과 다를 수 있다. 특히 급행 노선은 정류장 수가 적어도 거리가 길다. 한 줄로 밝힌다.
- 실시간 도착 정보는 **첫 구간 탈 정류장**만 `get_bus_arrivals`로 한 번 조회한다. 두 번째 구간은 도착할 때쯤 다시 물어보라고 안내한다(지금 조회한 값은 그때 의미가 없다).
- 구간 중 `viaTurnaround`가 true인 것이 있으면 직통 노선 때와 같이 회차 안내를 붙인다.

결과가 비어 있으면(2번 이상 갈아타야 하거나, `checkedRoutes.truncated`로 일부 노선만 본 경우):

- 환승 경로를 지어내지 않는다.
- 목적지 근처의 다른 정류장 이름으로 다시 찾거나, 지도 앱의 길찾기를 쓰라고 솔직히 말한다.

환승 답변 예시:

```
○○에서 △△까지 한 번에 가는 버스는 없어서, 한 번 갈아타야 해요.

**추천: A번 → B번 (총 N정류장)**
1. 🚏 **○○(정류장 번호)**에서 A번 타기 · 약 5분 뒤 도착
2. **□□(정류장 번호)**에서 내려 같은 정류장에서 B번으로 갈아타기 (n정류장 뒤)
3. **△△(정류장 번호)**에서 내리기 (m정류장 뒤)

정류장 수 기준이라 실제 걸리는 시간은 달라질 수 있어요.
```

## 오류가 났을 때

- 도구가 "인증키" 관련 오류를 돌려주면 사용자에게 `DATA_GO_KR_SERVICE_KEY` 설정을 확인하라고 안내한다.
- "세션"이나 일시적 오류는 서버가 이미 재시도했다는 뜻이다. 잠시 뒤 다시 물어봐 달라고 안내한다.
