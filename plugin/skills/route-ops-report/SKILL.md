# 노선 운행 분석 리포트

운행관리자가 **지금 이 노선에 손볼 곳이 있는지** 1분 안에 판단할 수 있는 리포트를 만든다.
숫자 계산은 `analyze_headway` 도구가 하고, 이 스킬은 **판단 기준을 적용하고 해석해서 정리**한다.

## 준비

korea-transit MCP 도구가 필요하다. `korea-transit` 플러그인으로 설치했다면 이미 연결되어 있다.
`analyze_headway`(이름 앞에 플러그인 접두사가 붙을 수 있음)가 없으면 설치를 안내한다.

```
/plugin marketplace add 98Woonho/korea-transit-mcp
/plugin install korea-transit@korea-transit-mcp
```

## 진행 순서

1. **도시:** `list_cities(query)`로 cityCode를 얻는다. 도시를 모르면 묻는다. 서울은 지원하지 않는다.
2. **노선:** `search_routes(cityCode, routeNo)`로 routeId를 찾는다. 같은 번호가 여러 개면(유형이나 기점이 다르면) 기점·종점을 보여 주고 사용자에게 고르게 한다.
3. **분석:** `analyze_headway(cityCode, routeId)`를 호출한다. 이 결과 하나에 리포트에 필요한 숫자가 거의 다 들어 있다.
4. **판정:** [references/criteria.md](references/criteria.md)의 기준으로 간격마다 등급을 매기고, 노선 전체 등급을 정한다. **처음 리포트를 만들 때는 이 파일을 반드시 읽는다.** 기준의 근거와 예외(회차 구간 등)가 그 파일에 있다.
5. **리포트:** 아래 형식으로 작성한다.

여러 노선을 요청받으면 노선마다 2~4단계를 거친 뒤, 맨 위에 노선별 요약 표를 하나 두고 노선별 상세를 아래에 붙인다.

## 리포트 형식

```markdown
# {노선번호}번 운행 상태 리포트
{도시} · {analyzedAt} · {요일 유형} 계획 배차 {scheduledIntervalMin}분

## 요약
- 전체 등급: **{양호 / 주의 / 개선 필요}**
- {가장 중요한 이슈 한 줄}
- {두 번째 이슈 또는 "그 밖의 구간은 균등에 가깝게 운행 중"}

## 운행 지표
| 항목 | 값 |
|---|---|
| 운행 대수 | {busCount}대 (위치 미확인 차량이 있으면 "+ 위치 미확인 n대") |
| 노선 정류장 | {totalStops}개 |
| 균등 간격 | {idealGapStops}정류장 (≈ {scheduledIntervalMin}분) |
| 정상 / 몰림 / 공백 구간 | {n} / {n} / {n} (회차·기점 통과 구간 {n}개 판정 제외) |

## 주요 이슈
| 구분 | 뒤차 → 앞차 | 위치 | 간격 | 추정 |
|---|---|---|---|---|
| 🔴 심한 몰림 | 대전75자3323 → 3313 | 정류장A → 정류장B | 1정류장 (×0.19) | 약 2분 |
| 🟠 공백 | 대전75자3303 → 3309 | ... | 8정류장 (×1.48) | 약 16분 |

## 참고 조치
- {criteria.md의 조치 예시 중 해당하는 것. 결정은 운행관리자의 몫임을 전제로}

## 데이터 한계
- {analyze_headway 결과의 notes를 요약. 회차 구간이나 공휴일처럼 해당하는 것만}
```

작성할 때 지킬 것:

- **위치는 정류장 이름으로** 쓴다. `buses`에서 차량번호로 `stopName`을 찾는다. 순번만 쓰면 현장에서 알아볼 수 없다.
- 이슈가 없는 정상 구간은 표에 나열하지 않는다. 개수만 지표에 남긴다. 리포트를 읽는 사람이 찾는 건 문제 구간이다.
- **추정치임을 숨기지 않는다.** "약 ○분"으로 쓰고, 데이터 한계 절에 근거를 남긴다. 공공 API에는 차량별 운행 시각이 없어서 정류장 간격으로 추정한 값이다.
- 운행 대수가 2대 미만이거나 운행 중인 차가 없으면(심야, 운행 시작 전) 리포트 대신 그 사실과 첫차·막차(`get_route_info`)를 알려 준다.
- 한 번의 분석은 **그 순간의 스냅숏**이다. 몰림이 심하면 "5~10분 뒤 다시 분석해서 해소되는지 보라"고 권한다. 흐름은 여러 번 봐야 판단할 수 있다.

## 사용자가 기준을 바꾸고 싶어 할 때

운수사마다 관리 기준이 다르다. 사용자가 다른 기준(예: "우리는 배차간격의 2배부터 공백으로 본다")을 말하면 그 기준을 우선 적용하고, 리포트 머리에 적용한 기준을 한 줄로 밝힌다.
